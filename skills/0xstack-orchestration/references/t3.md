# T3 Code execution

Discover current tool schemas. Names may carry an MCP namespace prefix. The following contract was checked against T3's live tools and official documentation. Use the installed schema when it changes.

## Discover targets

Call `orchestrator_capabilities` before the first delegation in a thread. Registered provider instance IDs are the source of truth. Keep `driverKind` distinct from `providerInstanceId`. Filter by `canRunChildTask`, account for cross-provider restrictions, and report each unavailable provider's `constraints`. Do not hardcode a provider allowlist.

Each model's `options` gives valid option IDs, values, and defaults. Options can differ by model and provider. Examples include `reasoningEffort`, `effort`, and `variant`; these are examples, not interchangeable names.

If `omittedModels` is positive, the initial model list is incomplete. Use the capability tool's `search` argument for a configured model or requested family. Merge the responses by provider instance ID and model ID. A configured model missing from a short list is not proven unavailable until its discovery search completes. Preserve unavailable choices and request replacements.

Outside MCP clients can see subagent tools but cannot use them without an active T3 parent. Report this limitation in explicit T3 mode. In auto, this does not qualify as a usable T3 delegation backend. Starting top-level threads is a different operation and requires the user's separate request.

## Launch

Build the self-contained brief and save a prepared attempt before calling `delegate_task`. Supply explicit `target.providerInstanceId`, `target.model`, and supported `target.options`. An empty options object clears inherited options. Include the role's validated options to avoid accidental parent-setting leakage.

Use the saved request ID as `clientRequestId`. Use `isolation: "worktree"` for independent code writers. `shared` is appropriate only for workers whose ownership cannot conflict. Backend-managed isolation prepares the checkout. Do not create a child's checkout in the shell or tell the child to create it.

The `role` argument is an optional T3 category with a fixed enum. 0xStack roles such as `how explorer` go in the task brief. Do not pass them as that argument. Do not raise `runtimeMode` or override interaction settings unless authorized. Role settings belong under `target.options`, never in invented top-level effort fields.

A worktree starts from the parent commit and omits uncommitted edits. For review, provide a patch artifact and its revision information. Have the child apply the patch only within its isolated checkout, then verify that it contains the intended diff before running review checks. Transfer untracked in-scope files separately. Keep patch artifacts private and limited to the task. If the task needs a different repository or project, verify `target.projectId` and the available schema before dispatch.

## Results, failure, and cancellation

Save `taskId`, returned child identity, provider, target, and worktree information immediately. A wait timeout leaves the child running. Record uncertainty instead of launching another copy.

Follow the returned `next` instruction. When completion wakes the parent, end the turn as instructed and resume on that notification. Do not poll a running task, add timers, or use an unrelated wait tool to bypass this contract. After notification or during explicit recovery, `task_status({taskId})` returns the summary and marks it delivered. Account for `hasPendingChildRuns` and `workState`; an ended child turn with live descendants is not completed work.

Handle pending questions through the installed pending-request tool on the returned child thread. Leave human approvals to their authorized owner. Pending questions and approvals are waiting states, not failures. A failed or interrupted worker needs its terminal evidence and partial-work inspection before retry. Record model and authentication errors without changing the saved assignment.

Cancel through `task_cancel({taskId, reason})`. It cancels the task's running and queued turns, descendants, and watches. `cancel_requested` is a request, not proof of terminal cancellation. Preserve completed results if cancellation races with completion. Never interrupt a child thread as a substitute.

If a response is lost, preserve `clientRequestId` and inspect the original request through the installed recovery facilities before retry. Do not assume generic exactly-once semantics from the presence of a request ID. If no supported lookup can recover a missing task ID, report the attempt as unknown and require reconciliation. Never create a replacement or switch backend to escape uncertainty.
